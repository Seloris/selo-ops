# Run trail

Pages: `sessions-live` · Domain: `session` · Components: `api`, `web`

## Spec delta
- session + BR-22 — A session's type of work is its current run's flow (« libre », fastlane, blueprint, autopilot), followed by « › {skill} » while a selo skill other than the flow runs (« autopilot › build », « libre › review »), as the export gives them; a session written by an export older than 2.5.0 has its run's lane read as that flow and skill, and a session outside selo reads « hors selo » (BR-12).
- sessions-live ~ FR-11 — « … the type of work (« libre », « hors selo » for a session outside selo (`session` BR-12), fastlane, blueprint, build, autopilot…) and the project … » → « A row holds two lines. The first shows the state's badge, the request on the rest of the line (cut with « … » at its end, whole on hover) and the age at the end. The second shows, under the badge, the type of work (`session` BR-22) and the project unless grouped by project (« fastlane · selo-ops »); then the context: what is awaited when the session is « à traiter » (its icon and text in the state's colour), else the step of a running session (« Étape 2 · tests du web »), else the « Action suivante » as a violet chip with its command (FR-21), else « Rien d'attendu »; then the count of files the session modified (a file icon and the number, « 3 fichiers modifiés » on hover; none at 0 or for a session outside selo) and the session's total tokens (`session` BR-18, abbreviated as in FR-35; none when the export gives no usage). The « Action suivante » (when the session has one, FR-21), « Note » and « Ouvrir dans Claude Code » icon buttons close the row, across both lines; a session with a note (`session` BR-21) has its « Note » button in blue, and hovering or focusing it shows the whole note in a small card under the button. The list has no column header. Below 900 px of width, the request takes its own line under the badge and the age, and the line after it keeps only the context. »
- sessions-live + FR-41 — « Déroulé du tour », in the detail, lists the current run's history as the export keeps it, oldest first: one line per change with its time, the skill, the step (« Étape 2 ») and substep, the state's badge and how long it lasted until the next line (none on the last); its heading sums the time spent in « Attend ta réponse » and « Commit à valider » (« 6 min à t'attendre »); when the export dropped the oldest entries a first line reads « Entrées plus anciennes non gardées par l'export »; the section is left out for a session outside selo and for one written by an export older than 2.5.0.
- sessions-live ~ FR-31 — « … folds « Fichiers modifiés », « Consommation », « Sous-agents » and « Modèle et permissions »; … » → « A click on a section's title in the detail folds the section to its title (its count still shown) or unfolds it; the folded sections are remembered in the browser, the same for every session, one set for the side panel and one for the full screen. By default the side panel shows « Ce qui est attendu », « Action suivante », « Peut-on fermer la session ? » and « Récap et commits » unfolded and folds « Déroulé du tour », « Fichiers modifiés », « Consommation », « Sous-agents » and « Modèle et permissions »; the full screen folds none. A section with nothing to show beyond its heading (nothing awaited, nothing blocking the close, no subagent, no file modified) is its heading alone, its summary on it, and neither folds nor unfolds. »
- sessions-live + Non-goal: « The history of a subagent's run: an autopilot's main run already carries its subagents' skills. »

## Business decisions
- Type of work → `flow › skill`, the skill left out when null or equal to the flow (the flow says how the work is driven, the skill what runs now)
- Timeline → its own detail section « Déroulé du tour », folded in the side panel, unfolded in full screen (FR-31)
- Waiting time → the sum of « Attend ta réponse » and « Commit à valider » durations, the ended ones only (a wait still open counts once it ends)
- Old exports → no timeline rather than a fake one built from `lane` (2.5.0 is the first to write `trail`)

### Decided during build
- Folded sections already saved in the browser → kept as saved: « Déroulé du tour » shows unfolded in the side panel until folded once (the saved set wins over the defaults, as for every section)

## Technical defaults
- Contract → `Session` loses `lane`, gains `flow` (string), `skill` (nullable), `trail` (`{ at, skill, step, substep, phase }[]`, [] when none) and `isTrailCut`; handoff regenerated
- Parsing → `lane`, `flow`, `skill` optional; `trail` read leniently (`.catch([])`, each field a string or null): a malformed trail never drops the session file
- Pre-2.5.0 mapping, in the API → `lane` `build`/`blueprint` → flow `blueprint`; `fastlane`, `autopilot` → themselves; `free`, `review`, `try`, `grill`, `setup` → `free`; skill = the lane when it is a skill name, else null
- Outside selo → flow `free`, skill null, trail []; the web keeps « hors selo » from `isOutsideSelo`
- Step → unchanged: the web already reads only `stage:N`, so an old `step: "free"` shows nothing
- Durations → `at` of the next entry minus this one's, formatted like the age (FR-14's units)
- Section place → right after « Récap et commits »
- Demo and fixtures → a 2.5.0 autopilot session whose trail goes autopilot › blueprint › build stage:1…review with an awaiting-commit stretch, one with `trailCut: true`, one 2.4.0 session with `lane: "build"` and no trail, one file with no `lane` at all

### Decided during build
- Trail entry's phase → read as one of the export's phases, `SessionState` in the contract; an entry with another phase or a malformed field is dropped, its siblings kept (the web badges it like a state)
- `trailCut` malformed → false (lenient like `trail`)
- Demo trail → on the one-step-checkout autopilot session, ending at its current `stage:1` tests rather than review (its row stays as the other browser tests know it); `trailCut` on the sessions-live build; the harbor-mobile review session written with no `lane` (flow `free`, skill `review`)
- Trail heading → the number of entries as its count; the waiting total shown folded or not, none when the run never waited; a line reads its time, `skill · step`, the state's badge and its duration
- Section hue → its own `--hue-trail`, lime, with a timeline icon

## Stages
1. api — `feat(run-trail): api — flow, skill and trail of the current run`
2. web — `feat(run-trail): web — type of work as flow › skill and the run's timeline`

## Tests

- web: type label (`autopilot › build`, `fastlane`, `libre › review`, `hors selo`); timeline durations, waiting total, the cut line, section absent with an empty trail
- browser: demo autopilot session — label in the row, the card and the detail, timeline unfolded and folded; desktop and 390 px
