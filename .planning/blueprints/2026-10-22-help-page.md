# Help page

Pages: `help` (new, `Route: /help`) · Components: `web`

## Spec delta
- help + FR-01 — The page opens with a short table of contents linking to its four sections, in this order: choosing a lane, the lifecycle of a piece of work, skills and agents, specs and vocabulary.
- help + FR-02 — The "choosing a lane" section explains when to take the fastlane (one page or one component, no new entity or business rule), the blueprint then build (a new page, entity or rule, or several pages) and the autopilot (the person leaves), with the prompt of each.
- help + FR-03 — The "choosing a lane" section holds a decision guide of yes/no questions that ends on one lane, so that a person picks a lane without reading every skill.
- help + FR-04 — The "lifecycle" section shows the steps of a piece of work in order (grill, blueprint, its one yes, stages with one commit each, review, full suites, browser test, spec merged, done footer) and which lane runs which step.
- help + FR-05 — The "lifecycle" section explains the two places commits go: on the base branch, committed as the work goes; in a worktree, on its branch, then landed as one squashed commit on the person's yes; and that no agent ever pushes.
- help + FR-06 — The "skills and agents" section shows one card per skill (fastlane, blueprint, build, autopilot, grill, review, try, run, setup) with what it does, when to use it, its prompt and its options (`— autonomous`, `— no browser`, `— demo`…).
- help + FR-07 — The "skills and agents" section shows one card per subagent role (reviewer, runner, explorer, implementer) with what it does, what it never does and the manifest role it runs on (`models.reviewer`, `models.runner`…).
- help + FR-08 — The "specs and vocabulary" section defines page spec, page stub, domain sheet, FR, BR, Q, spec delta, blueprint, stage, `Spec:` line and done footer, each in one or two sentences.
- help + FR-09 — The page reads no data: it shows the same content with the API down.
- help + Non-goal: « Content generated from the selo plugin's files: the page is written by hand and updated when selo changes. »
- help + Non-goal: « A link to the page from a navigation shell: none exists yet; the page is reached by its URL. »

## Business decisions
- Where does the content come from? → Hand-written French text in the app (static, no API call; the plugin's files are English and change shape).
- Which sections? → Choosing a lane, lifecycle, skills and agents, specs and vocabulary.
- How is the page reached? → Its URL only for now (no shell yet; a header link comes with the shell).

## Technical defaults
- Translation layer → the front's first, per its CLAUDE.md i18n rule; French only, keys `help.{element}.{text}`, no library for one language.
- Long texts and lists (cards, glossary, decision guide) → arrays of keys in a typed content module of the feature, rendered by `ui` components; no Markdown, no HTML in the strings.
- Decision guide → static nested yes/no list (or `<details>`), no state machine; anchors (`#lanes`, `#lifecycle`, `#skills`, `#vocabulary`) for the table of contents.
- Layout → `Panel` and `PageTitle` of `shared/ui`; a card grid of one column under 640px.
